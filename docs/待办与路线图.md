## 阶段 1 · 提醒精确到时分 + 本地日历授权闭环（先做）

**目标：** 说"11月3号下午3点打疫苗" → Agent 解析出 `15:00` → 写入 macOS Calendar → 到 14:50 系统弹通知。

### 改动清单

- [x] `reminders.due_time TEXT`（可空，`HH:MM`）；迁移 `ALTER TABLE`
  - 文件：`server/db.py`
- [x] 提醒模型与 API 接收 `due_time`（正则 `^([01]\d|2[0-3]):[0-5]\d$`）
  - 文件：`server/main.py`（`CreateReminderBody` / `PatchReminderBody`）、`server/tools.py`（`manage_reminder`）
- [x] 日历事件按 `due_time` 建日程（不再统一 09:00）
  - 文件：`server/calendar_sync.py`（`_create_local_event`）；alarm 仍按 `LOCAL_CALENDAR_ALERT_MINUTES`
- [x] 启发式解析抽时间（"下午3点 / 15点 / 3:00"）
  - 文件：`server/tools.py`（`_guess_iso_date` 旁加 `_guess_time`）
- [x] 前端提醒表单加可选时间输入（`<input type="time">`）
  - 文件：`web/src/components/ReminderBoard.tsx`
- [x] 前端"同步到系统日历"开关 + 状态反馈（调 `sync_status`）
  - 文件：`web/src/components/ReminderBoard.tsx`
- [x] 首次同步触发授权：点"同步到系统日历" → 后端 osascript → 系统 TCC 弹窗 → 返回 ok / perm_denied
  - 文件：`web/src/components/ReminderBoard.tsx`；接口 `POST /api/reminders/{id}/sync-calendar`
- [x] 失败降级：应用内看板 + 浏览器通知（永远兜底，不阻塞用户）
- [x] macOS 上无任何日历配置时默认启用本机日历（`CALENDAR_SYNC_PROVIDER` 留空也生效）
  - 文件：`server/calendar_sync.py`（`_normalize_provider`）
- [ ] 验收：真实说一句"11月3号下午3点打疫苗"，看 macOS 日历与通知

### 必须记住的事实

- **本地日历只服务后端所在那台 Mac**：网页无法直接访问 macOS Calendar，只能通过后端 osascript；其他设备访问此网页，提醒**仍只弹在后端那台 Mac**。
- **TCC 授权弹窗由 macOS 弹，不是网页弹**：网页只能发请求等结果；首次失败给"系统设置 → 隐私与安全性 → 自动化"引导。
- **公网部署后本地日历方案失效**：Linux 服务器无 osascript / Calendar.app；届时改云日历。

## 阶段 2 · 单用户密码登录（紧跟阶段 1）

**目标：** 所有 `/api/*` 需登录；Cookie session；前端有登录页；面试能讲清鉴权链路。

### 改动清单

- [x] `users` 表（`id/password_hash/created_at`）+ `auth_sessions` 表（`sid/user_id/expires_at`）
  - 文件：`server/db.py`
- [x] 新 `server/auth.py`：bcrypt 哈希、`hash_password` / `verify_password` / `start_session` / `resolve_session` / Cookie 读写
  - 文件：`server/auth.py`、`server/requirements.txt`（新增 `bcrypt`）
- [x] 路由：`POST /api/auth/setup`（首次设密码，已设则禁用）/ `/login` / `/logout` / `GET /me` / `GET /auth/status`
  - 文件：`server/main.py`
- [x] 全局鉴权：`@app.middleware("http")` 拦截 `auth_guard`，除 `/api/health` 与 `/api/auth/{status,setup,login}` 外全部需会话 Cookie
  - 文件：`server/main.py`
- [x] CORS 收紧 + Cookie 策略（`httpOnly + SameSite=Lax`，本地 HTTP 不强制 Secure，可用 `AUTH_COOKIE_SECURE` 打开）；CORS 最后注册以处于鉴权外层
  - 文件：`server/main.py`、`server/.env.example`（`CORS_ALLOW_ORIGINS` / `AUTH_SESSION_TTL_DAYS` / `AUTH_COOKIE_SECURE`）
- [x] 前端登录页 + 启动探 `/api/auth/status` + 401 拦截（顶层 view 状态切换，未引 router）
  - 文件：`web/src/components/LoginPage.tsx`、`web/src/App.tsx`、`web/src/api/client.ts`（`credentials: 'include'` + `setUnauthorizedHandler`）
- [x] 退出登录入口
  - 文件：`web/src/components/AboutDrawer.tsx`（「登录」区块 + 退出按钮）
- [x] `/api/metrics/*` 已收进鉴权后（用户面板不暴露，运维面留着）
- [ ] LLM Key 决策：单用户密码下仍全局；面试要能讲"多用户下应改 per-user Key 或平台代理计费"

### 面试叙事点

- 密码哈希选型（bcrypt，自带 salt + 可调 cost；argon2 更强但需额外依赖）
- Cookie session vs JWT 取舍（可服务端吊销 vs 无状态；单机本地选前者）
- CSRF（走 Cookie 就要处理；本地单用户 + SameSite=Lax 风险低）
- CORS 收紧与 SameSite、Cookie 顺序陷阱（CORS 必须在鉴权外层）
- FastAPI 中间件鉴权 vs `Depends` 依赖注入的取舍

## 阶段 3 · AI 应用补充（岗位最高 ROI）

- [x] **3.1 RAG 多路召回**：BM25 + 向量并行（JD 点名"多路召回"）
  - 文件：`server/rag.py` / `server/vector_store.py`
  - 实现：`_tokenize`（中英混合）+ 纯 Python `bm25_scores`（k1=1.5 / b=0.75）+ 向量稠密召回，两路并行取 `recall_k = top_k * 3`
- [x] **3.2 重排序**：轻量融合重排（RRF + 词面覆盖度）
  - 文件：`server/rag.py`
  - 取舍：本机未缓存 cross-encoder、外网下载不稳定；改用 RRF（k=60）融合两路名次 + 归一化后叠加覆盖度权重 0.35，零新增依赖、可复现
  - 输出片段含 `vector_score / bm25_score / coverage`，`reason` 说明两路召回条数
- [x] **3.3 Agent Memory（轻量）**：用户常用城市 / 上次提醒标题 / 偏好
  - 文件：新 `server/memory.py` + db 表 `agent_memory`
  - 实现：工具成功后 `observe()` 落库（`get_weather→city`、`web_search→last_search`、`manage_reminder add→last_reminder`）；`get_weather` 无 city 时 `recall("city")` 兜底；生成前 `build_memory_hint()` 拼进 system prompt
- [x] **3.4 评测集扩充**：RAG 命中率 / 引用准确率 / 幻觉率
  - 文件：`server/eval_agent.py`
  - 实现：`RAG_CASES`（租赁/劳动/信贷三例长文书）+ `_check_rag()` 离线算命中率与引用准确率；`--llm` 下 `_check_grounding()` 以"答案数字是否都在原文"估算幻觉率
  - 结果：命中率 3/3 = 100%，引用准确率 3/5 = 60%
- [x] **3.5 流式 Tool Calling**：边生成边出 tool 元信息
  - 文件：`server/stream_engine.py` / `server/main.py` / `web/src/hooks/useSseStream.ts` / `web/src/components/MessageArea.tsx`
  - 实现：`GenerationJob.tool_events` + `push_tool_event()`，在「规划 → 开始执行 → 执行完成」三个节点各推一条事件并 `notify()` 唤醒 SSE 循环；新增 SSE `tool` 事件整表推送（重连幂等）；前端 `onTool` → `Message.toolEvents` → 生成中显示「XX 进行中…」虚线芯片，结束后由 `agent` 事件的最终芯片接管
  - 取舍：只做编排层的工具生命周期事件，未改 `llm.py` 的 tool_calls 增量解析（模型选工具仍是一次非流式调用，收益低、风险高）
