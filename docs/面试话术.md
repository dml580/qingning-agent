# 青柠 · 面试话术（阶段 C）

用「生活文书实时工作台」讲前端工程能力时，可按下面四段展开。数字以本地演示为准。

---

## 1. 流式状态机（别把半截写成成功）

**一句话：** 助手消息有明确生命周期，取消/失败会保留半截内容，但状态不会落成 `completed`。

**路径：** `connecting → generating → completed | failed | cancelled`

**可追问怎么答：**

- 为什么要状态机？SSE 会断、会重试；若只靠「有没有字」判断完成，中断后刷新会把半截当成成功，产品语义错。
- 落库：后端在干净 `done` 才 `settle(completed)`；`cancel` / 异常走对应终态，content 已写入的保留。

**对应代码印象：** `server/stream_engine.py` 的 `settle`；前端 `Message.status` + 重试按钮。

---

## 2. `seq` 去重与断线续传

**一句话：** 每个 chunk 带单调递增 `seq`；前端记 `lastSeq`，重复丢弃；重连带 `from_seq` / `Last-Event-ID`。

**可追问怎么答：**

- 为什么会有重复？代理缓冲、浏览器自动重连、客户端主动 `from_seq` 续传时，服务端可能从缓冲回放已见过的段。
- 为什么不用只拼字符串？乱序或重复会导致内容错乱；按 seq 幂等更稳。

**对应代码印象：** SSE 事件带 `id`/`seq`；`useSseStream` / Workbench 里 `lastSeq`。

---

## 3. 长回复虚拟列表（对比面板是证据）

**一句话：** 长文按行拆；虚拟列表只挂视口附近节点；对比面板可开关，展示「总行数 vs 挂载节点 / FPS」。

**可追问怎么答：**

- 流式时不按 token 新建气泡，只改同一条 `content`，避免几千次挂载。
- 关掉虚拟列表后挂载节点≈总行数，滚动更重——这是简历截图素材（见 `docs/virtual-list-compare.md`）。

---

## 4. 模版化提示词与多模型通道正交

**一句话：** `catalog` 管场景系统提示词；「模型设置」管提供商 / Key / Base URL；两者解耦。

**隐私一句：** Key 只存本机后端（`.env` 或 `server/data/llm_runtime.json`），接口只回脱敏 hint，前端不持有明文。

**提示词精修：** 排在阶段 D，面试可说「通道与模版已拆开，内容质量用真实样例验收后再迭代」。

---

## 演示顺序（2～3 分钟）

1. 选模版 → 发送 → 看流状态 pill。  
2. 生成中点「中断」→ 半截保留、状态 `cancelled` → 点重试。  
3. 打开「虚拟列表对比」→ 关/开虚拟列表看挂载节点变化。  
4. （可选）「模型设置」说明 Key 落点。
