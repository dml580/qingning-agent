# 迷你 RAG（青柠加分项）

**状态：** 文书默认启用；短文自动跳过；无用户开关（面向产品，不暴露技术选项）。  
**代码：** `server/rag.py`；请求体仍可带 `use_rag`（前端文书恒为 true）。

## 流程

1. 用户粘贴文书发送（无需勾选）  
2. 正文够长则按约 280 字切块（重叠约 50）  
3. 用「模版关键词 + 文首」做关键词重叠打分，取 Top-K  
4. 将【检索片段】注入本轮 LLM 提示词；库中仍存用户原文  
5. 真正启用时气泡显示「已引用原文 N 段」

## 面试怎么讲

- **产品决策：** 面向用户不放「RAG 开关」——默认做对的事；短文自动降级为全文分析。  
- **为什么要 RAG：** 长文塞满上下文易丢重点；检索后再答，降低胡编、便于标出处。  
- **和微调比：** 文书条款常变 → 检索更新文档比改权重划算。  
- **局限（诚实）：** 当前是关键词检索，不是 embedding；阶段 2 可换向量库 / 评测集。

## 怎么试

1. 粘贴 `docs/提示词验收样例.md` 里较长套文（建议 >200 字）并发送  
2. 看气泡是否出现「已引用原文 N 段」，回复是否提到「片段N」
