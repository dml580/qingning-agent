# 学习路线：AI 前端 → AI 应用 → 预训练 / DPO·RLHF

**用途：** 没事时按阶段学；主投工作时优先 **阶段 1**，不要跳到阶段 3。  
**上次整理：** 2026-10-22  
**主项目锚点：** 本仓库「青柠」生活助理 Agent。

---

## 总览（三条线别混）

| 阶段 | 目标岗位/能力 | 和青柠关系 | 优先级 |
|------|----------------|------------|--------|
| **1. AI 前端** | 流式聊天、React/TS、体验与工程 | 已基本具备，补演示与边角 | ★★★★★ 先做 |
| **2. AI 应用** | RAG、轻量 Agent/工具调用、评测 | 在青柠生活助理 Agent 上扩展 | ★★★★☆ 有空再做 |
| **3. 预训练 / DPO·RLHF** | 模型训练与对齐全流程 | 独立专题，不必绑青柠 | ★★☆☆☆ 长线兴趣 |

### 防忘：微调 / DPO / RL 在哪一阶？

- **不在阶段 2（AI 应用）里当必做。**  
  AI 应用学的是：提示词、RAG、工具调用、评测、接好模型。面试能说清「RAG 和微调谁更划算」即可，**不必自己训一轮**。  
- **在阶段 3（长线）里。**  
  微调（SFT）、DPO、RL/RLHF、预训练 = 改模型权重，有 GPU / 转模型岗再系统学。  
- **阶段 1（AI 前端）更不用。** 前端只负责调用与展示。

## 阶段 2 · AI 应用

在「会做前端」之上，补「会做 LLM 应用落地」。

> **本阶段不含：从零预训练、完整 DPO/RLHF 实操。**  
> 那些在 **阶段 3**。这里最多「概念上知道微调是什么、何时不如 RAG」。

### 2.1 核心专题

1. **提示词与模版**（你已有 catalog）— 验收集、防胡编  
2. **RAG 最小闭环** — 分块 → embedding → 检索 → 带出处回答  
3. **轻量 Agent / Tool calling** — 2～3 个工具 + 状态机编排（不必上复杂框架）  
4. **评测** — 10～50 条样例：是否编造数字、是否引用原文  
5. **可插拔模型** — 云 API + 本地 Ollama（或 Windows 推理机）文档化  
6. （概念即可）**微调 vs RAG**：何时该检索增强、何时才值得 SFT——不要求本阶段动手训模型  

### 2.2 建议在青柠上的落地顺序

1. RAG 默认启用（无面向用户的技术开关）— **迷你版已落地**（关键词检索；阶段 2 可再换成 embedding + 向量库）  
2. 文档：`docs/rag与评测.md`（自建）  
3. 一个 tool 示例：如「抽取金额日期」或「缺条款检查」  
4. 投递话术：应用层控制行为，模型可替换；RAG 何时比微调更划算  

### 2.3 阶段 2 完成标准

- 能画一张架构图：前端 / API / 检索 / 模型。  
- 能解释：幻觉、温度、上下文长度、RAG vs 微调。  
- 可辅投：**AI 应用研发（初级/校招）**。

### 2.4 推荐方向（应用向）

- 检索增强（RAG）概念与朴素实现  
- OpenAI 兼容 API、function/tool calling 基础  
- 评测：人工 checklist + 简单自动规则（数字是否出自原文）

## 阶段 3 · 从零预训练、DPO / RLHF 全流程（长线）

> **注意：** 这是模型训练向；与 AI 前端主线正交。算力不足时只学概念 + 跟教程跑通小实验即可。  
> 你的 Mac 8GB **不适合**认真预训练；有独显的 Windows 更合适做微调实验。

### 3.0 先弄清名词（面试够用）

| 术语 | 一句话 |
|------|--------|
| **预训练 Pretraining** | 大规模无标注/弱标注语料上学习语言规律（从零或继续训底座） |
| **SFT** | 监督微调：用「标准问答对」教模型按格式/领域回答 |
| **RLHF** | 人类反馈强化学习：偏好数据 → 奖励模型 → RL 优化策略 |
| **DPO** | 直接偏好优化：用「A 优于 B」数据拟合偏好，通常比经典 RLHF 好落地 |
| **对齐 Alignment** | 让模型更安全、更听话、更符合人类偏好的统称（含 SFT/DPO/RLHF 等） |

### 3.1 学习顺序（不要一上来预训练）

1. **Transformer / LLM 推理基础**（token、context、采样）  
2. **SFT 微调一条龙**（小模型 + 小数据集 + LoRA）  
3. **偏好数据与 DPO**（理解再实操）  
4. **RLHF 经典流水线**（RM + PPO/同类，知其贵与难）  
5. **预训练（了解级）** — 数据规模、算力、阶段目标；除非有集群，否则只读书/看课  

### 3.2 可执行小实验（有 GPU 时）

- [ ] 用 LLaMA-Factory / Unsloth 等对 1.5B～7B 做 **LoRA SFT**  
- [ ] 准备 100～1000 条领域对话（可从文书分析改写）  
- [ ] 导出 GGUF → **Ollama create** → 接到青柠「自定义兼容接口」  
- [ ] （进阶）构造偏好对，跑一次 **DPO** 教程级实验  
- [ ] （了解）读一篇 RLHF/DPO 综述，能画流程图  

### 3.3 阶段 3 完成标准（兴趣向）

- 能画：预训练 → SFT → 偏好对齐（DPO 或 RLHF）→ 部署。  
- 能说明：Ollama 是推理不是训练；真训练在别的框架。  
- **不作为**当前求职主叙事，除非转投算法/Agent 优化岗。
